Ce qui casse avant demain matin

bun server.ts --check passe, mais il ne vérifie que trois règles. Huit défauts reproduits avec les faux claude et gh, dans un dossier à part.

En bref

Trois choses à corriger avant d'allumer la relève : n'importe quel programme du Mac peut valider ou envoyer à ta place, une question peut partir seule en production, et deux demandes du même client en même temps se marchent dessus.

Ce qui tient : tout texte client est échappé dans la page, les preuves ne servent que des fichiers listés, les inconnus ne déclenchent rien, la clé API est retirée de l'environnement.

3 · À ranger

  • GET /api/state ne vérifie pas l'en-tête Host reproduit : Host: evil.example rend tous les tickets (attaque par rebond DNS).
  • La session Claude peut lire le mot de passe mail : security find-generic-password -s kaoly-clients-mail -w à confirmer, non essayé pour ne pas toucher au trousseau. Elle voit aussi les tickets des autres clients dans le dossier de données. Les interdits se contournent : git -C . push, gh api -X PUT …/merge.
  • state() lance security toutes les 2 s par fenêtre ouverte ; trousseau verrouillé, demande répétée à confirmer.
  • « Retirer » un client : un clic, pas de retour en arrière ; ses tickets en file plantent sur Cannot read properties of undefined (reading 'name').
  • Ticket classé sans suite : la PR et la branche restent ouvertes sur GitHub.
  • Retouche : les anciennes captures restent à côté des nouvelles, sans distinction.
  • Mail : pièces jointes sous 20 Mo chacune mais pas au total (Gmail refuse au-delà de 25) ; un mail à trois demandes donne trois réponses ; objet sans « Re: ».
  • WhatsApp : captures et vocaux du client ignorés (ZTEXT is not null) ; pour un groupe, le texte est seulement copié.
  • Retouche et Relancer passent outre MAX_SESSIONS.

  • Voir les pièces jointes du client dans le ticket : aujourd'hui seul Claude les reçoit.
  • L'étape qui a échoué, dite en mots (« GitHub n'a pas créé la PR ») plutôt que la sortie brute de git.
  • Un essai de bout en bout avec eval/faux : dossier temporaire, dépôt nu local, autre port. C'est ainsi que les cas ci-dessus ont été reproduits ; --check ne couvre que gate, strictest et matchContact.
